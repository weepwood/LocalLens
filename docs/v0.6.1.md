# LocalLens v0.6.1

`v0.6.1` 修复 Windows 一体化应用在实际下载和旧版本升级时仍表现为“纯客户端”的问题。

## 修复内容

### 唯一的普通 Windows 下载包

普通用户使用：

```text
LocalLens-Windows-x64.zip
```

不再使用容易误解的 `LocalLens-Client-Windows-x64.zip` 名称。

独立服务端 `LocalLens-Server-Windows-x64.zip` 继续保留，但只用于高级部署。

### 强制包含内置服务端

最终 Windows ZIP 必须包含：

```text
LocalLens-Windows-x64/
├── LocalLens.exe
├── BUNDLE-MANIFEST.json
└── runtime/
    ├── LocalLensServer.exe
    └── media-tools/
        └── README.txt
```

打包过程缺少任何必要文件都会直接失败。

### 发布资产冒烟测试

CI 不再只检查构建目录，而会：

1. 解压最终 ZIP；
2. 从解压目录启动 `runtime/LocalLensServer.exe`；
3. 创建临时媒体目录和 SQLite 数据目录；
4. 使用独立测试端口运行；
5. 轮询 `/api/v1/health`；
6. 健康检查通过后关闭服务端；
7. 只有测试成功才上传 Windows Artifact。

### 构建清单

`BUNDLE-MANIFEST.json` 包含：

- 包名；
- 客户端版本；
- 服务端版本；
- Git 提交 SHA；
- GitHub Actions 构建编号；
- 内置服务端相对路径；
- UTC 构建时间。

### 旧版配置迁移

旧版客户端没有保存连接模式，只保存服务器地址和 Token。此前升级到一体化版本后，这类配置会被默认解释为远程连接，导致用户看不到本机服务端设置向导。

新版检测到旧配置后会显示选择页面：

- **使用本机内置服务器**：清除旧连接设置并进入本机媒体库初始化；
- **继续连接原来的服务器**：保留旧地址和 Token，并明确写入远程模式。

迁移操作不会删除远程服务器数据，也不会修改用户原始媒体文件。

### 更明确的缺包错误

首次启动找不到 `runtime\LocalLensServer.exe` 时，界面会明确提示：

- 当前目录不是完整的一体化安装包；
- 应下载 `LocalLens-Windows-x64.zip`；
- 必须完整解压后再运行 `LocalLens.exe`。

## FFmpeg 边界

Windows 包默认不附带 FFmpeg，但这与内置服务端是两件不同的事情：

- `runtime\LocalLensServer.exe`：必须随包附带；
- `runtime\media-tools\ffmpeg.exe`：可选；
- `runtime\media-tools\ffprobe.exe`：可选。

缺少 FFmpeg 会影响视频缩略图、部分格式元数据和 HLS 转码，不会导致 Go 服务端缺失。

## 升级建议

1. 下载 `LocalLens-Windows-x64.zip`；
2. 解压到新目录，不要覆盖旧目录中的零散文件；
3. 确认 `runtime\LocalLensServer.exe` 存在；
4. 启动 `LocalLens.exe`；
5. 根据提示选择本机模式或原远程服务器模式。
