# LocalLens × Lap 对齐说明

## 目标

本次重构以 Lap 的桌面信息架构、空间密度与媒体浏览工作流作为参考，将 LocalLens Windows 桌面端调整为更接近专业本地相册管理器的工作区。

这里的“对齐”分为两个层面：

1. **视觉与交互对齐**：窗口框架、图标轨道、上下文侧栏、媒体画布、紧凑工具栏、底部状态栏、设置页结构和暗色体验；
2. **功能能力对齐**：日历、地点、相机、人脸、智能相册、AI 搜索、集合托盘、重复项清理、内置查看器和编辑器等。

当前 PR 完成第一层，并把 LocalLens 已有能力嵌入新的工作区。第二层需要继续扩展 Rust 数据模型、索引任务和 Tauri 命令，不能仅靠前端样式完成。

## 实现边界

LocalLens 与 Lap 的基础架构不同：

- LocalLens：React + Tauri 2 + Rust/Axum + SQLite，并保留 Android 客户端和局域网 API；
- Lap：Vue + Tauri 2 + Rust + SQLite，主要是单机桌面相册应用。

因此本次不直接复制或替换 Lap 仓库代码，而是在 LocalLens 现有架构中重新实现相近的信息架构和交互模式。这样可以保留：

- Android 二维码配对与设备 Token；
- 局域网媒体访问；
- HTTP Range、字幕和 HLS 转码；
- LocalLens 现有数据库、扫描、缩略图与元数据队列；
- Windows 内嵌 Rust 服务生命周期管理。

## 许可证边界

Lap 使用 GPL-3.0-or-later，LocalLens 当前使用 MIT。

本次改动只参考公开界面结构和用户工作流，重新编写 React/TypeScript 与 CSS；没有复制 Lap 的 Vue 组件、Rust 源码、图标资源、图片资源或样式文件。后续开发也应维持这一边界。若未来直接引入或改写 Lap 的 GPL 源码，需要重新评估 LocalLens 整体分发许可证。

## 后续建议顺序

1. 时间线分组、虚拟滚动和内置查看器；
2. 相机/镜头聚合、智能相册和集合托盘；
3. 重复项检测、四图比较与清理流程；
4. 地图与 GPS 聚类；
5. 本地 AI 搜索、人脸检测与人物管理；
6. 图片编辑和更广泛格式支持。

优先顺序以用户可感知价值和工程风险为依据：先完善高频浏览体验，再引入模型下载、向量索引和人脸数据等高成本能力。
