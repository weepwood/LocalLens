# LocalLens v0.2.2

`v0.2.2` 针对大型媒体库中缩略图长期失败、任务永久卡死和当前页面缩略图排队过久的问题进行修复。

## 适用场景

- 媒体库包含数万张图片；
- 服务端没有安装 FFmpeg，导致所有图片缩略图失败；
- 后来补充 FFmpeg 后，旧任务仍然不再执行；
- 删除过 `data/thumbnails`，但数据库中的任务仍显示为 `done`；
- 当前打开的页面需要等待全部后台任务完成后才显示缩略图。

## 新的缩略图策略

### 常见图片

以下格式由 Go 服务端原生解码和生成 JPEG 缩略图：

- JPEG / JPG
- PNG
- GIF（使用首帧）

这些图片不再要求安装 `ffmpeg.exe`。

### 兼容格式

以下格式先尝试原生解码，失败后使用 FFmpeg：

- HEIC / HEIF
- WEBP
- TIFF
- BMP
- 特殊编码或损坏容忍度较低的 JPEG

### 视频

视频缩略图仍然依赖 `ffmpeg.exe`。

## 大媒体库队列优化

- 图片和视频使用独立任务领取路径；
- 图片任务由固定原生 Worker 处理；
- 客户端当前请求的缩略图会进入高优先级队列；
- 后台仍会逐步完成整个媒体库的缩略图；
- 全量扫描期间 Worker 暂停领取任务，扫描完成后继续；
- 缓存文件丢失但任务为 `done` 时会自动重新生成。

## 自动恢复

首次启动 `v0.2.2` 时会执行 schema migration 9：

- 将旧版本中失败的图片缩略图任务恢复为待处理；
- 将尝试次数清零；
- 清除旧错误信息；
- 不修改原始图片和视频；
- 不要求删除 `locallens.db`。

服务启动日志会显示：

```json
{
  "msg": "thumbnail engine ready",
  "nativeFormats": ["jpeg", "png", "gif"],
  "recoveredJobs": 19876,
  "ffmpegPath": "C:\\LocalLens\\bin\\ffmpeg.exe",
  "ffmpegAvailable": false
}
```

`recoveredJobs` 表示本次自动恢复的旧缩略图任务数量。

## 诊断接口

使用管理员 Token 查询：

```powershell
$token = "config.json 中的 api_token"
$headers = @{ Authorization = "Bearer $token" }

Invoke-RestMethod `
  -Uri "http://127.0.0.1:9527/api/v1/thumbnails/diagnostics" `
  -Headers $headers
```

响应包含：

- 各任务状态数量；
- 最近 20 条失败任务及错误原因；
- FFmpeg 实际解析路径；
- FFmpeg 是否存在；
- 缩略图缓存目录。

## 手动重试失败任务

```powershell
Invoke-RestMethod `
  -Method Post `
  -Uri "http://127.0.0.1:9527/api/v1/thumbnails/retry" `
  -Headers $headers
```

图片任务进入原生队列，视频任务进入 FFmpeg 队列。

## 推荐配置

对于约 2 万张图片和数百个视频：

```json
{
  "thumbnail_workers": 2,
  "metadata_workers": 2,
  "auto_scan": true,
  "watch_files": true
}
```

机械硬盘建议保持 1～2 个缩略图 Worker。SSD 可以使用 2～4 个，但不建议直接设置为 8，以免同时解码大图造成明显内存和磁盘压力。

## 升级步骤

1. 关闭旧服务端；
2. 备份 `data` 目录；
3. 使用新版 `LocalLensServer.exe` 替换旧程序；
4. 保留原 `config.json` 和 `data`；
5. 启动新版服务端；
6. 查看 `thumbnail engine ready` 日志；
7. 使用诊断接口确认 `failed` 数量和错误原因。

无需删除数据库，也不建议删除原始媒体目录。
