# LocalLens v0.5.0

`v0.5.0` 开始把 LocalLens 的视频播放从“直接请求原文件”升级为可协商、可诊断、按需生成兼容版本的视频媒体管线。

## 播放决策

客户端打开视频时先向服务端提交当前平台、支持的编码和容器、最大显示尺寸以及用户选择的清晰度。

服务端按照以下顺序决策：

1. 原始编码、容器和分辨率都兼容时，返回原文件 Direct Play 地址。
2. 原始文件不兼容，或用户手工选择兼容清晰度时，进入持久化转码队列。
3. 转码完成后返回 HLS 播放列表。
4. 转码尚未完成时返回 `202 Accepted`、进度和建议轮询间隔。
5. FFmpeg 缺失或任务失败时返回可读错误，客户端提供重试和 720p 兼容模式入口。

本版本没有预先转码媒体库中的全部视频。只有客户端首次请求对应清晰度时，服务端才生成缓存。

## 兼容清晰度

播放器菜单提供：

- 自动 / 原始画质
- 1080p 兼容模式
- 720p 兼容模式
- 480p 兼容模式

兼容版本统一使用：

- 视频：H.264
- 像素格式：YUV 4:2:0
- 音频：AAC 128 kbps 双声道
- 协议：HLS VOD
- 分段时长：6 秒

切换清晰度时会保存当前进度，兼容版本准备完成后从原位置继续播放。

## 持久化转码队列

SQLite 新增 `transcode_jobs`：

- `media_id`
- `profile`
- `source_modified_at`
- `status`
- `attempts`
- `progress`
- `last_error`
- `created_at`
- `updated_at`

任务状态包括：

- `pending`
- `running`
- `done`
- `failed`

服务异常退出后，处于 `running` 的任务会在下次启动时恢复为 `pending`。

## 固定 Worker

配置示例：

```json
{
  "transcode_workers": 1,
  "transcode_cache_gb": 20,
  "transcode_hardware": "software"
}
```

建议普通家庭服务器先使用一个转码 Worker。多个视频同时转码会明显增加 CPU、磁盘和内存压力。

`transcode_workers` 支持 1～4，默认 1。

## 硬件加速入口

`transcode_hardware` 可选：

- `software`：libx264 软件编码，默认值
- `nvenc`：NVIDIA NVENC
- `qsv`：Intel Quick Sync Video
- `amf`：AMD AMF

硬件模式要求所使用的 FFmpeg 构建包含对应编码器，并且 Windows 已安装正确的显卡驱动。配置错误时任务会进入失败状态并记录 FFmpeg 错误。

## 缓存管理

兼容视频保存在：

```text
<data_dir>/transcodes/<media-id>/<profile>/
```

缓存超过 `transcode_cache_gb` 后，服务端按照目录最后使用时间清理较旧的兼容版本。正在生成的工作目录和刚完成的当前版本不会被本轮清理删除。

删除兼容缓存不会影响原视频。下次播放时会重新生成。

## 外挂字幕发现

服务端会查找与视频同目录、同基础文件名的字幕：

```text
movie.mp4
movie.srt
movie.zh-CN.srt
movie.en.vtt
movie.ja.ass
```

支持发现：

- SRT
- ASS
- SSA
- WebVTT

字幕文件通过鉴权接口访问，不暴露服务器绝对路径。当前客户端会显示已发现的字幕列表；真正的轨道加载、样式控制和内嵌字幕选择将在后续子版本继续完善。

## 诊断接口

管理员可查看：

```http
GET /api/v1/transcodes/diagnostics
```

返回：

- 各状态任务数量
- 最近 20 个失败任务
- FFmpeg 路径和可用状态
- 转码硬件模式
- Worker 数量
- 缓存目录
- 当前缓存占用
- 缓存上限

重试失败任务：

```http
POST /api/v1/transcodes/retry
```

## 升级

现有数据库会自动创建转码任务表，原照片、视频和现有播放进度不受影响。

保留原来的：

```text
config.json
data/
bin/
```

把新配置项加入 `config.json`，再替换服务端和客户端程序即可。不需要重新扫描媒体库。
