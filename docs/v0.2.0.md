# LocalLens v0.2.0

## 升级前

1. 停止正在运行的 `LocalLensServer.exe`；
2. 备份服务端 `data` 目录，尤其是 `data/locallens.db`；
3. 保留原来的 `config.json`，并对照新的 `config.example.json` 增加配置；
4. 将同一版本的 Windows 服务端、Windows 客户端和 Android APK 一起升级。

原始图片和视频不在 `data` 目录中，升级不会搬动媒体文件。

## 新增配置

```json
{
  "public_url": "http://192.168.1.20:9527",
  "ffprobe_path": "./bin/ffprobe.exe",
  "watch_files": true,
  "thumbnail_workers": 2,
  "metadata_workers": 2,
  "pairing_ttl_minutes": 5
}
```

- `public_url`：二维码中写入的手机可访问地址；
- `ffprobe_path`：视频元数据提取程序；
- `watch_files`：是否启用实时文件监听；
- `thumbnail_workers`：缩略图最大并发数，建议 1～4；
- `metadata_workers`：元数据最大并发数，建议 1～4；
- `pairing_ttl_minutes`：一次性二维码有效分钟数。

## 自动数据库迁移

服务端首次启动时，会将 v0.1 数据库升级到 schema version 8，增加：

- 媒体拍摄时间、尺寸、时长、编码、GPS、相机和评分字段；
- 文件夹索引；
- 缩略图任务；
- 元数据任务；
- 设备和播放进度；
- 相册、标签及其关联表。

已有收藏和媒体索引会保留。迁移不需要重新创建数据库。

## 首次启动后的行为

1. 服务端恢复未完成的任务；
2. 根据 `auto_scan` 决定是否执行全量扫描；
3. 媒体被加入元数据和缩略图队列；
4. 元数据完成后，时间线会逐步从文件修改时间切换到 EXIF 或视频容器时间；
5. `fsnotify` 开始监听后续文件变化。

大型媒体库首次升级时，后台任务可能持续较长时间，但媒体列表仍可浏览。

## FFmpeg 与 FFprobe

Release 不捆绑 FFmpeg。请自行放置：

```text
LocalLens-Server-Windows-x64/
├── LocalLensServer.exe
├── config.json
└── bin/
    ├── ffmpeg.exe
    └── ffprobe.exe
```

没有 FFmpeg：原图和直接视频播放仍可使用，但缩略图无法生成。

没有 FFprobe：基础索引仍可使用，但视频时长、分辨率、编码和容器时间不会提取。

## 手机重新连接

v0.1 手动 Token 仍然兼容。更推荐：

1. Windows 客户端使用管理员 Token 连接；
2. 进入“服务器与设备”；
3. 生成二维码；
4. Android 客户端首次页面选择“扫描二维码配对”；
5. 手机领取独立设备 Token。

二维码只能领取一次，并会在配置时间后过期。

## 回滚

v0.2 数据库增加了新表和新字段。需要回滚到 v0.1 时：

1. 停止 v0.2 服务端；
2. 恢复升级前备份的整个 `data` 目录；
3. 使用 v0.1 服务端和客户端。

不要让 v0.1 服务端继续写入已经迁移到 v0.2 的数据库。

## 已知限制

- 暂无 HLS 自动转码；
- 暂无内置 HTTPS；
- 暂无 Windows Service / 托盘程序；
- Android 包仍为测试签名；
- iOS 尚未生成发布包；
- HEIC 和 RAW 支持取决于本机 FFmpeg 构建。
